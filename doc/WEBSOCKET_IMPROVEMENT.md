# WebSocket 개선: 자동 재연결과 바이너리 프레임 전송

대상: 지문자 실시간 인식 (`/api/v1/learning/ws/recognition`, `frontend/js/sign_learn.js`)

## 1. 문제

| 문제 | 영향 |
|---|---|
| 연결이 끊기면 `WebSocket 오류`만 표시하고 멈춤 | 네트워크가 잠깐 끊기거나 서버가 재시작되면 사용자가 학습을 처음부터 다시 시작해야 함 |
| 프레임을 base64 문자열로 바꿔 JSON에 담아 전송 | base64 인코딩으로 전송량이 약 33% 증가, 서버도 매번 JSON 파싱과 base64 디코딩을 수행 |
| 프레임마다 `target`, `subcategory`를 반복 전송 | 바뀌지 않는 값을 초당 여러 번 중복 전송 |
| 이전 프레임 인코딩이 끝나기 전에 다음 프레임 처리 | 느린 기기에서 프레임이 쌓일 수 있음 |

## 2. 개선 내용

### 2-1. 자동 재연결 (프론트)

- 연결이 끊기면 **지수 백오프**로 재연결합니다: 1초 → 2초 → 4초 → 8초(최대).
- 최대 10회까지 시도하고, 그래도 실패하면 `연결 실패 — 페이지를 새로고침해 주세요`를 표시합니다.
- 사용자가 단계를 넘기는 등 **의도적으로 종료한 경우**(`stopWebSocket`)에는 재연결하지 않습니다.
- 재연결에 성공하면 시도 횟수를 0으로 초기화합니다.
- 학습 타이머는 **처음 연결될 때만** 시작합니다. 재연결 때마다 카운트다운이 초기화되는 문제를 막기 위해서입니다.

화면 상태 문구:

| 상태 | 문구 |
|---|---|
| 처음 연결 시도 | `연결중...` |
| 연결 성공 | `연결 완료` |
| 끊김 감지 | `연결 끊김 — N초 후 재연결 (N회)` |
| 재연결 시도 | `재연결 중 (N회)...` |
| 재시도 한도 초과 | `연결 실패 — 페이지를 새로고침해 주세요` |

### 2-2. 바이너리 프레임 전송 (프론트 + 백엔드)

- 프론트는 `canvas.toBlob("image/jpeg", 0.85)`로 만든 JPEG를 **바이너리 그대로** 전송합니다.
- `target`, `subcategory`는 별도의 `config` 메시지로 **연결 직후와 값이 바뀔 때만** 보냅니다.
- 이전 프레임 인코딩이 끝나지 않았으면 다음 프레임을 건너뜁니다.
- 백엔드는 `ws.receive()`로 텍스트와 바이너리를 모두 받습니다.
  - 바이너리: JPEG 바이트를 바로 디코딩
  - 텍스트 `config`: 대상 정보 저장
  - 텍스트 `frame`(기존 base64 방식): **하위 호환을 위해 그대로 지원**

메시지 형식:

```text
클라이언트 → 서버
  {"type": "config", "target": "ㄱ", "subcategory": "자음"}   // 텍스트, 연결 직후·변경 시 1회
  <JPEG 바이너리>                                             // 프레임마다
  {"type": "frame", "image": "data:image/jpeg;base64,...", ...} // 기존 방식 (계속 지원)

서버 → 클라이언트 (변경 없음)
  {"type": "prediction", "hand_detected": true, "top3": [...], "score": 92.1, "is_passed": true}
```

## 3. 변경 파일

- `frontend/js/sign_learn.js`: `startWebSocket`, `connectRecognitionSocket`, `stopWebSocket`, `startFrameSender`, `stopFrameSender`
- `main/api/learning/learning_routes.py`: `recognition_ws` 수신 로직
- `frontend/html/sign_learn.html`: 스크립트 버전을 `?v=261101`로 올림 (브라우저 캐시 때문에 옛 JS가 실행되는 문제 방지)

## 4. 검증

| 항목 | 방법 | 결과 |
|---|---|---|
| 바이너리 프레임 처리 | Python WebSocket 클라이언트로 `config` + JPEG 바이너리 전송 | `prediction` 응답 수신 |
| 하위 호환 | 같은 연결에서 기존 base64 `frame` 메시지 전송 | `prediction` 응답 수신 |
| 자동 재연결 | 크롬에서 연결 후 서버를 종료했다가 재시작 | `연결 완료` → `연결 끊김 — 1초 후 재연결 (1회)` → `연결 끊김 — 2초 후 재연결 (2회)` → … → `연결 완료`로 복구 |
| 문법 | `node --check`, `ast.parse` | 통과 |

참고: 크롬은 실패한 WebSocket 연결이 반복되면 자체적으로 재시도 간격을 늦추기 때문에, 서버가 다시 켜진 뒤 실제 재연결까지 수 초가 더 걸릴 수 있습니다.

## 5. 기대 효과

- 짧은 네트워크 끊김이나 서버 재시작(배포 포함) 시 사용자가 학습을 이어갈 수 있음
- 프레임당 전송량 약 25% 감소 (계산값: base64는 원본의 4/3 크기이므로 바이너리로 보내면 약 1/4이 줄어듦. 실측은 아직 안 함)
- 서버의 JSON 파싱과 base64 디코딩 비용 제거

## 6. 남은 과제

- 단어(`/ws/word_recognition`)와 문장(`/ws/video_recognition`) 인식에는 아직 적용하지 않았습니다. 두 엔드포인트는 연결마다 상태(모션, 프레임 버퍼)를 들고 있어서, 재연결 시 상태를 어떻게 이어갈지 별도 설계가 필요합니다.
- 하트비트(ping/pong)로 조용히 끊긴 연결을 더 빨리 감지하는 기능은 아직 없습니다.
- 실제 전송량 감소는 수치로 측정하지 않았습니다. 포트폴리오에 수치를 쓰려면 개발자 도구 Network 탭에서 전후를 측정하는 것을 권장합니다.
